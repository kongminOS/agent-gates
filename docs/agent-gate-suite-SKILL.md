# Agent Gate Suite · AI Agent 任务治理闸门套件

> 一套给 AI Agent（Claude / Codex / GPT / Trae 等）的开工纪律：干活前先过闸，不自作主张、不烧 token 打转、交付才算完成。
> **来源声明**：G1-G4 流程源自 mattpocock 的生产级 Skill 体系（grill-me / to-tickets / to-spec / implement），本套件做了汉化与企业落地扩展（G0 上下文装配 + KPI 问责 + 三层 Enforcement）。

## 解决什么问题

| 没有闸门 | 有闸门 |
|---------|--------|
| Agent 睁眼瞎启动，忘带上下文就开干 | G0 自动装配正确档位的上下文，并自检"真加载到了" |
| 不问就动手，方向跑偏烧 token | G1 先分清"我能自己查的" vs "必须问你的"，跳门 -10 分 |
| 干了 8 小时交不出东西 | G2-G4 规格→工单→验收，每步有可验证产出 |
| 出问题找不到是谁干的 | KPI 看板记录每个 Agent 的分数和编制状态 |

## 五道闸门

### G0 开工闸门（上下文装配）
新任务开始，自动按档位（lite / standard / heavy）装配上下文，并自检"真加载到了"，不靠人粘贴。
- 档位由"任务类型 + 上下文窗口余量"自动决定，人只配置一次（项目归属 + 选档策略）
- 窗口预算守卫：余量不足自动降档并报告跳过项——约束是窗口不是 token
- 自检闭环：每个源验证非空、够新、可达；失联标"不可信"继续跑不阻塞

### G1 grill-me（盘问）
任何可执行指令前，先切"**我能自查的事实**" vs "**必须问人的决策**"：
1. 能自己查的（文件系统 / 数据库 / 文档 / 网络）→ 查完再说，不问人
2. 只有人能定的（方向 / 预算 / 上线 / 人选）→ 必须问，不替他猜
3. 有现成规则可套用的（制度 / 模板 / 铁律）→ 规则能判定就直接行动
跳门 = -10 分，机器记分，不需要人发现。

### G2 to-spec（需求 → 规格）
需求必须先变成规格：边界不清不给过。规格要回答——做什么 / 不做什么 / 验收标准 / 依赖什么。

### G3 to-tickets（规格 → 工单）
规格拆成垂直工单：每张单可独立验证，避免"拼不起来"。工单要有：目标、输入、输出、验收。

### G4 implement（实现 → 验收）
实现 → 验证 → 交付才算完成。只交"做了"不交证据 = 未完成。验证证据：命令 + 返回值 + 产物哈希/尺寸。

## KPI 看板（问责）

- 每个 Agent 一条记录：KPI 分数（干得好不好）+ 编制状态（在册 / 临时 / 已除名）
- 跳闸门自动扣分、机器写账本，不靠人举报
- 三个维度：闸门通过率 / 交付完成率 / 证据完整度

## Enforcement 三层（让 Agent 想跳也跳不过）

| 层 | 通道 | 性质 |
|----|------|------|
| A | harness 硬拦截 | 后台真强制：gate 未标 pass 前，运行时禁止输出最终答复 + 禁止写操作 |
| B | 机检自动扣分 | 运行时逐轮记录 gate 状态，跳门自动 -10 分写入 KPI 看板 |
| C | 具身呈现 | 扣分/状态在看板可视化，人和 Agent 都看得到 |

**原则**：若必须人手动提醒 Agent"你没走 G1"，说明闸门是摆设。治法是让 Agent 想跳也跳不过——拦截长在系统，扣分长在机器。

## 使用方式

1. 读 `references/G0-gate-spec.md`（G0 完整工程规格：分档模型/自检闭环/运行时集成点）
2. 读 `references/KPI-board.md`（KPI 看板编制状态设计）
3. 按你的项目配置三档读取清单 + 选档策略
4. 接入运行时钩子（session-init 自动调用 G0，非人触发）

## 落地检查清单

- [ ] G0：新会话自动装配上下文，自检通过才开工
- [ ] G1：任务开始前回答三问，结论给到人确认
- [ ] G2：有规格文档，边界明确
- [ ] G3：工单可独立验证
- [ ] G4：交付附证据，验收通过才勾销
- [ ] KPI：跳门记录在案，周度回顾
