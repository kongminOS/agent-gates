# Agent KPI 看板 · 编制状态维度设计

> 给没有 Agent 管理经验的人看的队伍结构：正式工 / 临时工 / 已开除。
> KPI 看"干得好不好"，编制看"靠不靠得住、谁负责"——双轴互补。

## 0. 来源

- 洞察：传统 KPI 只有分数/状态，没有"编制内/编制外"区分。客户无 Agent 经验，但靠此维度能一眼看懂队伍结构。
- 佐证：规格交付后，执行 Agent 自动拆步骤、自动派子 Agent 干活 → "AI 管 AI"成立的前提是交付物写清楚（报告质量决定拆解质量）。

## 1. 为什么加"编制状态"这一轴

- 客户不懂 Agent 拓扑，但懂"正式工 / 临时工 / 已开除"。
- 治理价值：暴露异常（如某 Agent 已除名却仍在干活），逼出决策，防止"影子 Agent"无人跟踪。

## 2. 维度定义（三态）

| 值 | 含义 | 例子 |
|----|------|------|
| 编制内 | 常驻、有定义角色 + KPI + 问责 | 总管 / 工程主 / 后端 / 审查·战略 |
| 编制外(临时) | 按任务临时调入，无常驻 KPI | 临时子 Agent / 外部 API |
| 已除名(仍调用) | 除名但仍在承担工作 | 异常旗标 |

## 3. 看板字段建议

`Agent | 角色 | 编制状态 | KPI | 状态 | 当前任务 | 归属项目`

- 视觉：编制内=实色块；编制外=虚线/描边；已除名=红删除线 + ⚠。

## 4. 客户价值

- 一眼分清：核心队 vs 临时工 vs 异常。
- 回答三个客户最该问的问题：我依赖谁？谁问责？什么是过渡？
- 把"Agent 治理"从黑盒变成可视结构，降低客户认知负担。

## 5. 与 G0 的协同

- G0 协议注册表可按项目绑定"编制内 Agent 清单"；看板读同一源 → 编制状态自动同步，不需人维护。
- 新客户 onboarding 时，G0 自动标注哪些 Agent 在本项目编制内。

## 6. 设计决策（实现前需拍板）

- 编制状态由谁定（人写 / 注册表自动 / 看板配置）？
- 是否把 KPI 表也加"编制"列（双源一致风险）？
- 已除名仍调用是否强制在客户看板标红 ⚠？
- 看板落地形态（UI / 文档 / 独立页）？

## 7. 验收标准

- [ ] 看板含编制状态列，三态可视觉区分。
- [ ] 异常 Agent 被标红 ⚠。
- [ ] 编制状态与 G0 注册表同源（可选）。
